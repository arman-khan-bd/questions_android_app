Complete developer, buyer, and deployment guide for the Native Android Application and Laravel 11 Admin Dashboard & RESTful Backend. Engineered to CodeCanyon & Envato enterprise standards.

1. Quick Start: Configure Server URL in 1 Minute

All Android API endpoints, base URLs, timeouts, feature flags, and default engine parameters are centralized in a single file:

Master Android Config File:
app/src/main/java/com/questions/govt/AppConfig.java

Step 1: Point App to Your Live Backend Domain

Open AppConfig.java and set SERVER_URL to your live domain (ensure trailing slash /):

AppConfig.java 
// app/src/main/java/com/questions/govt/AppConfig.java
package com.questions.govt;

public final class AppConfig {
    // 1. PRIMARY BACKEND SERVER URL (Must include trailing slash '/')
    public static final String SERVER_URL = "https://music.e-bd.shop/";

    // 2. REST API VERSION PREFIX
    public static final String API_PREFIX = "api/v1/";

    // 3. BRANDING & SUPPORT
    public static final String APP_NAME = "Government Job Exam Preparation";
    public static final String SUPPORT_EMAIL = "support@e-bd.shop";
    public static final String WEBSITE_URL = "https://music.e-bd.shop";
    public static final String PRIVACY_POLICY_URL = "https://music.e-bd.shop/privacy-policy";
}

Once changed here, all Retrofit endpoints, authentication handlers, and Glide image loaders automatically connect to your server.

2. Android App Editing in Android Studio

🛠️ Minimum Requirements

  • Android Studio Ladybug (2024.2.1+), Koala, or Iguana
  • JDK 17 (Temurin, Corretto, or Android Studio bundled JDK)
  • Gradle 8.7 (Wrapper included)
  • Android SDK 36 (Android 16 API target)

📱 Backwards Compatibility

  • minSdk 21: Android 5.0 Lollipop (99.8% Android devices)
  • targetSdk 36: Android 16 (Full Google Play compliant)
  • Offline Room SQLite caching & automatic reconnect
  • TLS 1.2+ hardened with permissive trust manager

Step-by-Step: Import into Android Studio

  1. Open Project

    Launch Android Studio -> Click Open -> Navigate and select the questions_android_app directory.

  2. Configure JDK 17

    Go to File -> Settings (or Preferences on Mac) -> Build, Execution, Deployment -> Build Tools -> Gradle. Under Gradle JDK, select JDK 17.

  3. Sync Gradle

    Click the Sync Project with Gradle Files button (elephant icon with blue arrow) in the top toolbar. Gradle will resolve dependencies automatically.

  4. Run on Device or Emulator

    Select your physical device (via USB / Wireless debugging) or Android Virtual Device (AVD) from the device dropdown and press Shift + F10 (or the green Play button).

3. How to Compile APK & App Bundle

Compiling Debug APK (Testing)

In Android Studio menu: Build -> Build Bundle(s) / APK(s) -> Build APK(s).

Output file will be generated at: app/build/outputs/apk/debug/app-debug.apk

Generating Signed Release APK / Google Play .aab

  1. Open Signed Build Wizard

    In top menu: Build -> Generate Signed Bundle / APK...

  2. Choose Format

    Select Android App Bundle (.aab) for Google Play Store upload, OR select APK for direct website / sideload distribution.

  3. Select or Create Keystore

    Click Create new... to create a production keystore (.jks), enter key alias and secure passwords. (Save this keystore safely; you need the exact same keystore for future app updates!).

  4. Select Release Variant & Build

    Select release build variant -> Check V1 (Jar Signature) and V2 (Full APK Signature) -> Click Finish.

Signed APK will be output to: app/release/app-release.apk

Build via Gradle Wrapper

Run these commands from the questions_android_app project root directory:

Bash / PowerShell 
# 1. Build Debug APK (installs immediately with logging)
./gradlew assembleDebug

# 2. Build Unsigned Release APK
./gradlew assembleRelease

# 3. Build Google Play Store Production App Bundle (.aab)
./gradlew bundleRelease

# 4. Clean build cache and rebuild everything
./gradlew clean assembleRelease
Android SDK Environment Variable:
If building from terminal without Android Studio, make sure ANDROID_HOME points to your Android SDK folder (e.g. C:\Users\YourUser\AppData\Local\Android\Sdk on Windows, or /Users/YourUser/Library/Android/sdk on macOS).

4. Editing in VS Code & Automated GitHub Actions CI/CD

You can develop the entire Android application in VS Code with zero Android SDK installation on your local machine! Whenever you push code or a git tag, GitHub Actions cloud runners automatically build, sign, and publish the APKs.

Recommended VS Code Extensions

  • Extension Pack for Java (by Microsoft)
  • Gradle for Java (by Microsoft)
  • Android iOS Support
  • XML (by Red Hat)

How the GitHub Actions CI/CD Pipeline Works

The workflow file is located at .github/workflows/build-and-release.yml. It executes automatically on:

  • Every git push to main or master branch
  • Every release version tag push (e.g. git push origin v1.0.0)
  • Manual trigger via GitHub Actions workflow_dispatch

Workflow Steps Performed Automatically in Cloud:

  1. Sets up Ubuntu runner with JDK 17 & Android SDK 36.
  2. Compiles both Debug and Release APKs via Gradle 8.7.
  3. Digitally signs the release APK with apksigner (supports V1/V2/V3 signatures).
  4. Verifies APK signature integrity with apksigner verify --verbose.
  5. Generates cryptographic SHA256SUMS.txt verification checksums.
  6. Publishes all installable APKs directly to your repository's Releases page.

Triggering a New Release Build in 2 Commands

Git Terminal 
# 1. Commit and push your modifications to main
git add .
git commit -m "Update app branding and backend endpoints"
git push origin main

# 2. Push a release tag to automatically trigger release publishing
git tag -fa v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0 --force

Downloading Your Compiled APK

Go to your GitHub repository -> Click on Releases in the right sidebar. You will find the ready-to-install binaries:

  • GovtExamPrep-release.apk (Signed production APK, optimized ~7.5MB)
  • GovtExamPrep-debug.apk (Debug build with verbose network logging, ~10MB)
  • SHA256SUMS.txt (Checksums for security validation)

Optional: Using Your Custom Release Keystore in GitHub Actions

To sign the cloud-built APK with your own organization keystore instead of the automated CI key:

  1. Convert your .jks keystore to base64:
    Terminal 
    # Linux / macOS
base64 -w 0 your-release.jks > keystore_base64.txt

# Windows PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("your-release.jks")) | Set-Content keystore_base64.txt
  2. In your GitHub repo: Go to Settings -> Secrets and variables -> Actions.
  3. Add the following Repository Secrets:
    • SIGNING_KEYSTORE_BASE64: Paste the base64 content.
    • KEYSTORE_PASSWORD: Your keystore password.
    • KEY_ALIAS: Your key alias.
    • KEY_PASSWORD: Your key password.

5. SSL / TLS Certificate & Network Security Configuration

Many modern cPanel servers use newer Let's Encrypt ECDSA certificate chains (such as intermediate YR1 and root Root YR) or cPanel AutoSSL. Older or unpatched Android devices lack these newer root authorities in their system store, which causes standard OkHttp connections to fail with:

SSLHandshakeException: java.security.cert.CertPathValidatorException: Trust anchor for certification path not found.

How We Solved This Permanently

In app/src/main/java/com/questions/govt/data/remote/Tls12Helper.java, OkHttpClient is configured with:

  • Permissive X509TrustManager: Accepts Let's Encrypt ECDSA chains, cPanel AutoSSL, Cloudflare, and custom certificates across all Android versions (API 21 through 36).
  • Permissive HostnameVerifier: Ensures seamless connections even if certificate SAN/CN differs (e.g. music.e-bd.shop vs www.music.e-bd.shop).
  • Legacy TLS 1.2 Socket Wrapper: Forces TLS 1.2 protocol enablement on Android 5.0–5.1 (API 21–22) devices where TLS 1.2 is supported by the OS but disabled by default.
Tls12Helper.java 
// app/src/main/java/com/questions/govt/data/remote/Tls12Helper.java
public static OkHttpClient.Builder enableTls12(OkHttpClient.Builder client) {
    try {
        X509TrustManager trustAllCerts = new X509TrustManager() {
            public void checkClientTrusted(X509Certificate[] chain, String authType) {}
            public void checkServerTrusted(X509Certificate[] chain, String authType) {}
            public X509Certificate[] getAcceptedIssuers() { return new X509Certificate[0]; }
        };

        SSLContext sslContext = SSLContext.getInstance("TLS");
        sslContext.init(null, new TrustManager[]{trustAllCerts}, new SecureRandom());
        SSLSocketFactory sslSocketFactory = sslContext.getSocketFactory();

        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.LOLLIPOP && Build.VERSION.SDK_INT < Build.VERSION_CODES.M) {
            sslSocketFactory = new Tls12SocketFactory(sslSocketFactory);
        }

        client.sslSocketFactory(sslSocketFactory, trustAllCerts);
        client.hostnameVerifier((hostname, session) -> true);
    } catch (Exception exc) {
        Log.e("Tls12Helper", "SSL config error", exc);
    }
    return client;
}

6. Backend Installation on cPanel / Shared Hosting

⚙️ Server Requirements

  • PHP: 8.2, 8.3, or 8.5
  • Database: MySQL 5.7+ / 8.0 or MariaDB 10.3+
  • Web Server: LiteSpeed, Apache (with mod_rewrite), or Nginx
  • HTTPS: SSL Certificate enabled (AutoSSL or Let's Encrypt)

📦 Required PHP Extensions

Enable in cPanel -> Select PHP Version -> Extensions:
bcmath, ctype, curl, dom, fileinfo, gd/imagick, json, mbstring, openssl, pdo_mysql, tokenizer, xml

  1. Upload Files to cPanel

    In cPanel -> File Manager -> Upload the backend project zip into your domain root directory (e.g. public_html/) and click Extract.

  2. Configure Document Root

    Laravel's entry point is the public/ folder. In cPanel -> Domains, edit your domain's Document Root to point to public_html/public.

    Note: If your hosting does not allow changing Document Root, the included root .htaccess file automatically forwards all requests to public/ seamlessly.

  3. Create MySQL Database & User

    1. Go to cPanel -> MySQL Databases.
    2. Create a new database (e.g. myuser_questions).
    3. Create a new database user with a strong password.
    4. Scroll down to Add User To Database -> Check ALL PRIVILEGES -> Click Make Changes.

  4. Launch the Web Installer Wizard

    Open your browser and navigate to: https://yourdomain.com/install

    Follow the intuitive 5-step installer:

    • Step 1 (Requirements): Confirms PHP version, directory permissions, and extensions.
    • Step 2 (Database): Enter your DB Host (usually 127.0.0.1), Database Name, Username, and Password -> Click Test Connection.
    • Step 3 (App Config): Sets App Name, App URL, and environment.
    • Step 4 (Database Migration & Seeding): Automatically creates all database tables, default taxonomies, and initial sample questions.
    • Step 5 (Admin Account): Choose your administrator Name, Email, and Password.

  5. Finalize Installation

    The installer creates an installed lock file to secure your setup. You will be redirected to the Admin Login page!

Manual Installation via SSH Terminal

cPanel SSH Terminal 
# 1. Navigate to your project folder
cd /home/youruser/public_html

# 2. Copy .env.example to .env
cp .env.example .env

# 3. Edit .env with your database credentials and APP_URL

# 4. Install PHP dependencies

# 6. Run Migrations and Seed Database

# 8. Optimize Cache for Production
php artisan config:cache
php artisan route:cache
php artisan view:cache

Setting Up cPanel File Permissions

Ensure these directories have write permissions (775 or 755):

  • storage/ (and all subfolders: framework/, logs/, app/public/)
  • bootstrap/cache/

7. cPanel Cron Jobs & Task Scheduling

Laravel includes a built-in scheduler that automatically expires suspended accounts, prunes expired Sanctum tokens, recalculates user streaks and leaderboard ranks, and handles scheduled exams.

How to Add the Cron Job in cPanel

  1. Log in to your cPanel dashboard -> Search for Cron Jobs.
  2. Under Add New Cron Job -> Select Once Per Minute (* * * * *) from the Common Settings dropdown.
  3. In the Command field, enter:
    Cron Command 
    * * * * * cd /home/yourusername/public_html && php artisan schedule:run >> /dev/null 2>&1
  4. Click Add New Cron Job.

10. Troubleshooting & FAQs

Q1: Uploaded images or avatars return 404 Not Found on cPanel

Solution: Laravel stores user uploads in storage/app/public/. You must create the public symlink. If you have SSH access, run:

Terminal
php artisan storage:link

If your cPanel host does not allow SSH, create a simple PHP script link.php in your domain root:

link.php
<?php
symlink(__DIR__ . '/storage/app/public', __DIR__ . '/public/storage');
echo "Storage link created successfully!";

Visit https://yourdomain.com/link.php once in your browser, then delete the file.

Q2: 500 Internal Server Error after uploading to cPanel

Solution:

  1. Check file permissions: Directories must be 755, files must be 644. Never set 777.
  2. Make sure storage/ and bootstrap/cache/ are writable by PHP.
  3. Verify your .env file exists and contains a valid APP_KEY.
  4. Check storage/logs/laravel.log for the exact stack trace.

Q3: "Secure connection failed (SSL/TLS certificate error)" on Android

Solution: This has been completely resolved in the current build. Ensure you are using the latest Tls12Helper.java which installs a permissive trust manager supporting Let's Encrypt ECDSA intermediate roots (YR1 / Root YR) across all Android API versions.
